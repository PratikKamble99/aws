        # IAM Policy inheritance 
            All user policies are inherit from group policy
            IAM policy structure
            1) Version: policy language version ( required )
            2) Id: Identifier for the policy ( optional )
            3) Statement: List of statements that define the policy ( required )

            If we attach direct policy to user then that policy and that policy known as inline policy.

            We can also create own policies with our custom permissions.

            Statement consist of
            1) Sid: Statement ID (optional)
            2) Effect: Wether Statement Allow or Deny Access (required)
            3) principle: account/role/user to which this policy applied to
            4) Action: list of actions that can be performed
            5) Resource: list of resources which can be applied to eg. your s3 bucket ect.
            6) Condition: list of conditions that must be met before the policy is applied ( optional )

        ## Security groups and classic ports overview
            1. Security groups are fundamental of network security in AWS
            2. They control how traffic allowed into or out of our EC2 instances
            3. Security groups contains only allow rules
            4. Security group rules are refer by Ip or by security group.
            5. Security groups are acting like "Firewall" on EC2 instance
            6. They regulate:
                a. Access to ports
                b. Authorized IP ranges - IPV4 and IPV6
                c. Control of inbound network ( from other to instance )
                d. Control of outbound network ( from instance to other )
            7. Security groups can be attached to multiple EC2 instances
            8. Locked down to region/VPC combination
            9. Does live outside of EC2 - if traffic is blocked by security group, instance will not see it.
            10. It's good to maintain a separate security group for SSH access.
            11. All inbound traffic blocked by default.
            12. All outbound traffic allowed by default.
            13. If your application is not accessible( time out ), then it's be security group issue.
            14. If your application gives "connection refused" error, then it's application error ot it's not launched.
            
        ## Classic ports
            1. 22 - SSH(Secure shell) - log in to linux
            2. 80 - HTTP - Access unsecure web server
            3. 443 - HTTPS - Access secure web server
            4. 3389 - RDP(Remote desktop protocol) - log in to windows instance
            5. 21 - FTP - file transfer protocol - uploads files into file share
            6. 22 - SFTP - Secure file transfer protocol - upload files using SSH

        ## EC2 purchasing options
        1. On demand: Short workload, predictable pricing, pay by seconds
            a. Linux and windows: Billing per sec, after first minute
            b. All other Operating Systems: billing per hour
            c. Highest cost, no upfront payments
            d. recommended for short term 

        2. Reserved :
            a. Reserved instances: Long workload, lower pricing, pay upfront
                1. up-to 70% discount compared on demand
                2. specific instance attributes ( region, instance type, OS, tenancy)
                3. Reservation period: 1 (+discount) to 3(+++discount) years 
                4. Payment options: No upfront(+ discount), partial upfront(++discount), all upfront(+++discount)
                5. Reserved instances scope: regional OR zonal
                6. Recommended for steady workload eg. database
                7. You can buy or sell your reserved instance in marketplace

            b. Convertible reserved instances: Long workload with flexible instances
                1. up-to 66% discount compared on demand
                2. Can change EC2 instance type, instance family, OS, Scope, tenancy

        3. Saving plans: Commitment to amount of usage, long workload
                1. Get discount based on long-term usage ( up to 70% discount)
                2. Commit to certain type of Usage ( $10 per hour for 1-23 years)
                3. Usage beyond EC2 Saving Plan is billed at the on Demand price 
                4. Locked to specific instance family & region
                5. Flexible across: Instance size, OS, tenancy(host, dedicated, default)

        4. Spot instances: Short workload, lower pricing, can loose instance
            a. Instance will loose if max price is less than current spot price
            b. Can be used for batch Jobs, data Analysis, Image processing, any distributed workloads, workload wth flexible start and end time
            c. Not suitable for database or critical workload
            
        5. Dedicated hosts: Book an entire physical server
            a. Purchasing options
                1. On demand: pay as per sec for dedicated host
                2. Reserved: 1 or 3 year
            b. Useful for companies that have strong regulatory and Compliance need

        6. Dedicated instance: No other customer will share your instance
            1. Instance runs on hardware that is dedicated to you
            2. May share hardware with other instance with sam account
            3. No control over instance replacement

        7. Capacity Reservations: Reserved capacity in a specific AZ for any duration.
            a. You always ave access to EC2 when you need it
            b. No time commitment: (Create/Cancel anytime), no billing discount
            c. to get discount you need to combine with regional reserve instance and saving plans
            d. You charged at on demand rate whether you run it or not

    # Amazon EC2 Instance Storage Section 
        What is EBS volume
            1. An EBS ( Elastic block store ) volume is a network that you can attach to your instance while the are running
            2. It allows you to persist data, even after the instance is terminated
            3. they can only be mounted to one instance at time( at ccp level )
            4. They are bounded to specific availability zone.
            5. We can attach one EBS volume to another instance.
            6. It's a network file ( not a physical drive )
                a. It uses network to communicate with the instance, means there might be latency
                b. It can be detach from instance anytime and quickly attached to another instance.
            7. It's Locked to availability zone
                a. An EBS volume n US-EAST-1A can not be attach to US-EAST-1B
                b. To move volume across availability zone, you need to create snapshot and restore it in another availability zone
            8. Have a provisioned capacity (Sizes in GiB, and IOPs)
                a. you get billed for all provisioned capacities
                b. You can increase the size of the volume over time

        # EBS Snapshots
            1. Make backup of EBS volume at any point in time
            2. Not necessary to detach volume to do snapshot, but recommended
            3. Can copy snapshot to across region or availability zone.

            Features:
                a. EBS snapshot archive
                    Move snapshots to an "archive tier" that is 75% cheaper.
                    Takes within 24 to 72 hours to restoring the archive.
                b. Recycle bin for EBS snapshots
                    Setup rules to retain deleted snapshots that you can recover them after accidental deletion.
                    specify retention ( from 1 day to 1 year ) 
                c. Fast snapshot Restore (FSR)
                    force full initialization of snapshot with no latency.
                    But this is costly
                    You can use this when volume is big, and you need to restore it quickly.

        # EBS volume Types
            1. gp2/gp3 (SSD) : it is with balanced price and performance for wide variety of workloads
                - cost effective storage, low-latency
                - system boot volume, virtual desktops, Development and test environment
                - 1 GiB to 16 TiB per volume
            2. io 1 /io 2 Block express : highest performance SSD volumes for mission critical, low-latency and high performance volume
            3. st 1 (HDD) : Low cost HDD designed for frequently access thoughput-intensive workload
            4. sc 1(HDD) : Lowest cost HDD volumes for less frequently access workload

        # EBS volum type use cases:
            1. provisioned IOPS ( PIOPS) SSD
                - critical business applications with sustained IOPS(Read/Write operations) performance
                - Or applications that need more than 16,000 IOPS
                - Great for databases workloads( sensitive to storage performance and consistency )

                - io1 type of volumns ( 4GiB - 16TiB)
                    - Max PIOPS per volume: 64,000 for nitro EC2 instance and 32000 for other 
                    - Can increase PIOPS indepenadlty from storage size
                - io2 type of volumns ( 4GiB - 64TiB)
                    - Sub-millisecond latency
                    - Max PIOPS: 256,000 with an IOPS:GiB ratio of 1000:1
                - Supports EBS multi-attach
            
            2. Hard Disk Drives (HDD)
                - Cannot be a boot volume -  primary storage device that contains the operating system
                - volumn size- 125 Gib to 16 TiB
                - Throughput optimized HDD (st1)
                    - Max throughput per volume: 500 MiB/s
                    - Great for big data, data warehouse, log processing
                - Cold HDD (sc1)
                    - For data that is infrequently access
                    - scenarios where lowest cost is important
                    - Max throughput per volume: 250 MiB/s - max IOPS 250

            # Multi Attach voolun for EBS
                - Attach the same EBS volume to multiple EC2 instances in the same availability zone
                - Each instance has full read and write permissions to the high performance volume
                - Use cases:
                    1. Achivee higher applications availability in clustered linux applications
                - Up to 16 EC2 Instance at time
                - Must use a file systme that's cluster aware ( not XFS, EXT4, etc ) 

    # Amazon EFS -( Elastic File Systems )
        - Managed NFS ( Network file system ) that can be mounted to multiple EC2 instances
        - EFS works with EC2 instances in multi availability zones
        - Higly available, Scalabale, expensive(3x gp2), pay per use

        - EFS use cases:
            1. Content management
            2. Web serving
            3. Wordpress
        - Uses NFSv4.1 protocol
        - Uses security group to control access to EFS
        - Only compatible with linux based EC2 instance ( not windows )
        - Encryption at rest and using KMS
        - POSIX file system ( ₹Linux ) that has a standard file application
        - File systme sclaes automatically, pay-per-use, no capacity planning
